# 복구 완전성 및 GPU 서버 초기화 기준

기준 커밋: `b4eda9ea95f64d7f449acdb1e27d5e173eaad8f8`

이 문서는 GPU 작업공간을 정리하기 전에 GitHub에 실제로 남아 있는 것과, 서버를 초기화한 뒤 다시 준비해야 하는 것을 구분한다. 공개 저장소에 개인 CCTV 원본·사람 crop·비밀키를 넣지 않는 원칙을 유지한다.

## 초기화 뒤 별도로 복원해야 하는 항목

| 항목 | 기록된 범위 | 의미 |
| --- | ---: | --- |
| 원본·중간 산출물 중 공개 제외 파일 | 7,793개 / 약 5.92 GiB | 비공개 CCTV·crop·캐시이므로 GitHub에 올리지 않음 |
| GPU 서버의 전체 모델 파일 | 198개 / 305.813 GiB | 목록과 크기만 보존, 전체 바이너리는 다시 다운로드하거나 사설 저장소에서 복원해야 함 |
| 선택 가중치 외의 학습 산출물 | 전체 바이너리 복구 보장 안 됨 | 정확히 같은 체크포인트가 필요하면 별도 백업 필요 |
| PA-100K·CHIRLA·프로젝트 CCTV 원본 | 비공개 데이터 루트 필요 | 데이터와 split을 복원한 뒤 manifest validator를 다시 실행해야 함 |

따라서 현재 저장소만으로는 코드와 실험 절차를 다시 실행할 수 있지만, 서버의 모든 가중치를 즉시 동일한 바이너리로 되살릴 수 있다고 볼 수는 없다. 특히 결과 숫자와 파라미터를 올려 둔 것만으로 학습된 모델 파일이 자동으로 복원되는 것은 아니다.

## 초기화 판정

다음 세 조건이 모두 확인되기 전에는 GPU 서버의 작업공간을 삭제하지 않는다.

1. 비공개 원본 데이터와 필요한 학습 체크포인트가 별도 저장소에 독립적으로 복사되어 있다.
2. 삭제 대상이 `i15a204`의 실제 작업공간으로 확인되고, 시스템·공용·다른 사용자의 경로가 아니다.
3. 복사본의 파일 수·바이트 수·SHA-256 readback이 원본 manifest와 일치한다.

현재 GitHub 백업은 공개 가능 산출물과 선택 가중치에 대해서만 검증되어 있다. 위 조건을 충족하지 않은 상태에서 서버를 초기화하면, 목록에는 남아 있어도 원본 체크포인트와 비공개 데이터가 복구되지 않을 수 있다.
