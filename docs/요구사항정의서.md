# 요구사항정의서(SRS)

> 문서 구분: 이 문서는 제품이 충족해야 할 목표 요구사항을 정의하며 현재 `dev`의 구현 현황을 나타내지 않는다. 실제 제공 기능과 API는 [REST API 명세서](<./API 명세서.md>)의 현재 제공 계약과 `dev` 코드를 기준으로 확인한다.

## 프로젝트 목표

- 골든 타임 내 단서 신속 확보
    - 실종 신고 후 48시간 이내에 유의미한 실종자 후보 단서를 빠르게 찾아내어 수색의 골든타임을 확보합니다.
- 관제자 의사결정 보조
    - 시스템이 실종자를 자동으로 확정하지 않고, 후보군을 좁혀주어 관제자의 영상 검토 부담을 줄이고 정확한 판단을 돕는 보조 역할을 수행합니다.
- 자연어 기반 즉각 탐색
    - 모델의 추가 재학습을 기다릴 필요 없이, 사건마다 달라지는 자연어 인상착의를 즉시 검색 프롬프트로 활용해 탐색을 시작합니다.
- 경로 기반 탐색 확장
    - 녹화본 후보 경로와 카메라 위치를 이용해 다음 탐색 대상을 정하고 AI 작업을 자동 등록합니다.

## 상위 요구사항

| 식별자 | 상위 요구사항명 | 설명 |
| --- | --- | --- |
| RE-SF1 | 회원 및 권한 관리 | 관제실 관리자와 수색 담당자 등 운영 사용자 유형별 회원 정보와 시스템 접근 권한을 관리한다. v1 신고자는 회원 계정 없이 진행 조회 기능만 이용한다. |
| RE-SF2 | 실종 신고 및 사건 관리 | 실종 신고를 접수하고 인상착의, 사진, 마지막 목격 위치·시각 등 사건 정보를 통합 관리한다. |
| RE-SF3 | 실종자 탐색 조건 관리 | 신고 정보를 바탕으로 자연어 인상착의, 탐색 시간대, CCTV 및 구역 등 사건별 탐색 조건을 설정한다. |
| RE-SF4 | 녹화 CCTV 영상 기반 실종자 탐색 | 마지막 목격 장소·시각부터 녹화본을 탐색하고 경로 기반 후속 작업을 AI Worker에 등록한다. |
| RE-SF5 | 실시간 영상 기반 실종자 탐색 | Jetson이 관할 카메라 4대에서 한 사건의 실시간 후보를 탐지한다. |
| RE-SF6 | 실종자 후보 검토 및 판정 | 실시간 후보를 우선 제시하고 관리자가 후보의 대상 여부를 판정한다. |
| RE-SF7 | 실종자 추정 동선 관리 | 관측 추정 경로와 관리자 확정 경로를 구분하고 다음 예상 카메라를 제공한다. |
| RE-SF8 | 수색 정보 공유 | 확인된 목격 위치, 시각, 수색 구역과 사건 진행 상태를 신고자 및 관계자(담당 경찰관 등)에게 권한에 따라 제공한다. |
| RE-SF9 | 사건 이력 및 관제 시스템 관리 | 후보 탐지, 관리자 판정, 상태 변경, 사건 종료 및 개인정보 처리 이력을 기록하고 관리한다. |

## 기능 요구사항 (Flow Chart)

| 상위 식별자 | 상위 요구사항명 | 식별자 | 기능 요구사항명 | 설명 |
| --- | --- | --- | --- | --- |
| RE-SF1 | 회원 및 권한 관리 | RE-SF1-01 | 역할 기반 사용자 로그인 | 시스템은 관제실 관리자, 수색 담당자(경찰관), 시스템 관리자 등 역할(Role)에 따른 가상 계정 로그인 기능을 제공해야 한다. |
|  |  | RE-SF1-02 | 사용자 역할 식별 | 로그인한 사용자의 역할을 식별하고 해당 역할 정보를 세션 또는 인증 정보에 포함해야 한다. |
|  |  | RE-SF1-03 | 역할별 접근 권한 제어 | 로그인한 사용자의 권한 등급에 따라 메뉴 노출 및 기능 실행 권한(예: 관제실 관리자는 판정 및 사건 관리 권한 보유, 수색 담당자는 읽기 및 동선 조회 권한만 보유)을 제한해야 한다. |
|  |  | RE-SF1-04 | 회원 정보 조회 및 수정 | 사용자는 자신의 기본 정보를 조회하고 허용된 범위에서 수정할 수 있어야 한다. |
|  |  | RE-SF1-05 | 담당 관계자 등록 | 관리자는 사건별로 담당 관제자와 경찰관 등 관계자를 등록할 수 있어야 한다. |
|  |  | RE-SF1-06 | 로그아웃 | 사용자는 로그인된 세션을 종료할 수 있어야 한다. |
| RE-SF2 | 실종 신고 및 사건 관리 | RE-SF2-01 | 관리자 사건(Case) 등록 및 ID 발급 | 로그인한 관리자는 전달받은 신고자 연락처, 실종 발생 시각, 마지막 목격 위치와 대상 기본 정보를 입력하여 사건을 등록할 수 있어야 하며, 시스템은 고유 사건 ID를 자동 생성해야 한다. |
|  |  | RE-SF2-02 | 사건 목록 및 상세 조회 | 시스템은 등록된 가상 사건의 전체 목록을 제공해야 하며, 특정 사건을 선택했을 때 해당 사건의 상세 인상착의 정보와 탐색 진행 상황을 한눈에 볼 수 있어야 한다. |
|  |  | RE-SF2-03 | 사건 상태 관리 | 관제실 관리자는 사건 상태를 신고 접수, 탐색 중, 후보 확인, 수색 진행, 사건 종료로 변경할 수 있어야 한다. |
|  |  | RE-SF2-04 | 사건 정보 수정 | 관제실 관리자는 새로운 목격 정보나 신고자 제공 정보가 발생했을 때 사건 정보를 수정할 수 있어야 한다. |
|  |  | RE-SF2-05 | 관리자 사건 입력 양식 제공 | 관리자는 신고자·실종자·마지막 목격 정보와 머리, 얼굴, 상·하의, 신발, 소지품, 체형, 특징으로 구조화된 인상착의를 입력할 수 있어야 한다. |
|  |  | RE-SF2-06 | 신고자 정보 스냅샷 저장 | 시스템은 관리자가 입력한 신고자 정보를 회원 계정이 아닌 사건 접수 당시의 스냅샷으로 저장해야 한다. v1에서는 사건마다 별도의 신고자 정보를 생성하며 전화번호가 같더라도 기존 정보를 재사용하지 않아야 한다. |
|  |  | RE-SF2-07 | 전화번호 검증 및 정규화 | 관리자 사건 등록·수정과 신고자 진행 조회의 전화번호에는 ASCII 숫자(`0`~`9`), ASCII 하이픈(`-`), ASCII 공백(`U+0020`)만 허용해야 한다. 시스템은 하이픈과 공백을 제거한 10~11자리 숫자를 저장·조회에 사용한다. |
|  |  | RE-SF2-08 | 사건 삭제 제한 | 사건 물리 삭제 API를 제공하지 않고 관리자가 사건 종료 상태로 전환해야 한다. 보관기한 만료 후 자동 파기는 후속 구현 범위로 관리한다. |
| RE-SF3 | 실종자 탐색 조건 관리 | RE-SF3-01 | 자연어 인상착의 프롬프트 설정 | 사건별로 '검은색 셔츠', '청바지' 등 의상, 소지품, 신체 특징을 키워드로 저장하고, 이후에 다중 자연어 텍스트 프롬프트로 입력하고 관리할 수 있어야 한다. |
|  |  | RE-SF3-02 | 탐색 범위 및 대상 카메라 지정 | 마지막 목격 장소·시각과 실제 위·경도가 등록된 CCTV를 기준으로 초기 탐색 범위를 설정할 수 있어야 한다. |
|  |  | RE-SF3-03 | 프롬프트 구조화 및 전송 | 입력된 키워드는 템플릿을 통해 자연어 프롬프트로 변환되고, 작동 중인 백엔드 서버 및 Jetson Orin Nano의 AI 엔진으로 즉시 동기화되어야 한다. |
| RE-SF4 | 녹화 CCTV 영상 기반 실종자 탐색 | RE-SF4-01 | 마지막 목격 기준 녹화본 탐색 | 사건 탐색이 시작되면 중앙 서버는 마지막 목격 장소·시각에 해당하는 녹화 분석 작업을 AI Worker에 등록해야 한다. |
|  |  | RE-SF4-02 | 과거 영상 내 후보 프레임 검출 | 누적 영상 탐색 중 설정된 사건 프롬프트와의 유사도 임계값을 초과하는 프레임을 검출하여 후보군으로 분류하고 DB에 저장해야 한다. |
|  |  | RE-SF4-03 | 녹화본 스캔 진행률 및 잔여 시간 표출 | 대시보드 화면에 과거 영상 스캔의 진행 상황(처리 완료 %, 남은 예상 시간)을 실시간으로 트래킹하여 관제자에게 표시해야 한다. |
|  |  | RE-SF4-04 | 후속 녹화 분석 작업 등록 | 관측 추정 경로가 만들어지면 중앙 서버는 카메라 위·경도를 기준으로 다음 예상 카메라를 최대 2대 선정하고 예상 도착 시각 전후 구간의 작업을 등록해야 한다. |
| RE-SF5 | 실시간 영상 기반 실종자 탐색 | RE-SF5-01 | AI 기반 실시간 실종자 탐지 | Jetson 1대는 관할 카메라 4대의 영상을 입력받아 한 번에 한 사건만 탐색해야 한다. |
|  |  | RE-SF5-02 | 엣지 자원 활용 최적화 (샘플링) | 엣지 디바이스에서 AI 모델을 사용하기 위해 tensorRT 및 경량화를 활용한다. 또한 실험적으로 최적화된 fps값을 산출하여 사용한다. |
|  |  | RE-SF5-03 | 실시간 후보 메타데이터 전송 | Jetson은 자체 유사도 임계값을 통과한 후보의 크롭 이미지, 카메라 ID와 탐지 시각을 서버로 즉시 전송해야 한다. |
|  |  | RE-SF5-04 | 실시간 후보 데이터 관리 | 서버는 Jetson 후보의 출처를 별도로 저장하고 관리자 판정 상태와 분리해 관리해야 한다. |
| RE-SF6 | 실종자 후보 검토 및 판정 | RE-SF6-01 | 실시간 후보 우선 표출 | 대시보드는 Jetson 실시간 후보를 녹화본 후보보다 목록 최상단에 표시하고 후보 출처를 구분해야 한다. |
|  |  | RE-SF6-02 | 전후 숏 클립(영상) 재생 | 관제자가 특정 이벤트를 클릭하면, 해당 후보가 탐지된 시각의 전후 수 초간의 CCTV 녹화 분량을 즉시 인라인 비디오 플레이어로 재생하여 전후 맥락을 검토할 수 있도록 해야 한다. |
|  |  | RE-SF6-03 | 관제자 3단계 판정 처리 및 이력 기록 | 대시보드는 각 후보 이벤트에 대해 관제자가 **[후보 유지], [대상 확인], [대상 아님]** 중 하나를 선택해 판정하고, 관련 판정 근거(텍스트)를 기록하는 기능 및 DB 저장 폼을 제공해야 한다. |
| RE-SF7 | 실종자 추정 동선 관리 | RE-SF7-01 | 관측 추정 경로 생성 | 시스템은 임계값 이상의 녹화본 후보를 탐지 시각과 카메라 위치 순서로 연결하여 내부 탐색용 관측 추정 경로를 생성해야 한다. |
|  |  | RE-SF7-02 | 다음 예상 카메라 선정 | 시스템은 최근 경로와 카메라의 실제 위·경도를 이용해 다음 예상 카메라를 최대 2대 선정해야 한다. |
|  |  | RE-SF7-03 | 확정 경로 관리 | 관리자가 [대상 확인]으로 판정한 후보만 별도 확정 경로에 포함하고 판정 변경 시 경로를 갱신해야 한다. |
|  |  | RE-SF7-04 | 경로 구분 표시 | 대시보드는 관측 추정 경로, 확정 경로와 다음 예상 카메라를 구분하여 표시해야 한다. |
| RE-SF8 | 수색 정보 공유 | RE-SF8-01 | 신고자용 실시간 사건 진행 현황 제공 | 신고자는 별도 로그인 없이 사건조회번호와 전화번호 조합으로 전용 간이 페이지에서 현재 탐색 상태(접수/스캔 중/검토 진행 중/완료)를 확인할 수 있어야 한다. 개인정보 보호를 위해 CCTV 원본 영상 및 다른 실종자 정보, 일반인 이미지는 차단해야 한다. |
|  |  | RE-SF8-02 | 현장 수색팀 즉각 최신 알림 전송 | 관제실 관리자가 후보를 [대상 확인]으로 판정하는 즉시, 현장 수색 담당자에게 최신 목격 시각, 카메라 위치와 후보 이미지를 전송해야 한다. |
|  |  | RE-SF8-03 | 수사자료 제공 | 수사자료에는 관리자 확정 후보의 경로 추적 정보와 그 경로를 기반으로 한 예측 결과만 포함해야 한다. |
| RE-SF9 | 사건 이력 및 관제 시스템 관리 | RE-SF9-01 | 후보 탐지 이력 관리 | 시스템은 사건별 녹화 영상 검색 결과와 실시간 후보 탐지 결과를 이력으로 저장해야 한다. |
|  |  | RE-SF9-02 | 감사 추적용 작업 로그(Audit Trail) 저장 | 탐색 조건, 자동 작업 등록, 경로 갱신, 관제자 판정과 시스템 상태 변경 이력을 감사 로그로 보존해야 한다. |
|  |  | RE-SF9-03 | 사건 상태 변경 이력 관리 | 시스템은 사건 접수, 탐색 시작, 후보 확인, 수색 진행과 사건 종료 등 상태 변경 이력을 저장해야 한다. |

    개인정보 및 보안 통제 - 원본 영상, 후보 이미지, 판정 로그에 대한 보관 기한을 설정 및 자동 삭제 처리하며, MVP 목적에 맞게 동의된 모의 데이터에만 접근하도록 안전 경계를 구축한다.
    

- 기능 적합성 (Functional Suitability)
    - 정확성 (Accuracy)
        - 통제된 10개 시나리오 중 8건 이상에서 Top-5 후보 내에 대상을 포함
    - 완전성 (Completeness)
        - 확정 이벤트의 시각, 카메라, 판정 근거 기록률 100%
- 성능 효율성 (Performance Efficiency)
    - 시간 반응성 (Time Behavior)
        - 실시간 스트림 기준 프레임 수신부터 대시보드 표시까지 5초 이내
    - 자원 활용성 (Resource Utilization)
        - 과저 1시간 영상 탐색 시, 수동 재생 대비 관제자 검토 시간 50% 이상 절감
- 보안성 (Security)
    - 기밀성 (Confidentiality)
        - 사건 식별자와 접근 권한 통제
    - 책임 추적성 (Accountability)
        - 모든 판정 로그, 장치 상태 이력, 접근 감사 로그 저장 및 보관기한 명시
- 신뢰성 (Reliability) 및 사용성 (Usability)
    - 결함 허용성 (Fault Tolerance)
        - AI 오탐/미탐 가능성을 고려하여 시스템 자동 출동을 배제하고, 관제자의 개입을 필수로 설정
    - 오류 방지 (User Error Protection)
        - AI가 도출한 유사도가 신원 및 범죄 가능성의 확정 근거가 아님을 UI에 명시하여 관제자의 인지적 오류 예방
