# 기능 명세서

역할:

- 임베디드
- 백엔드
    - 보안(회원 관리) → 윤현준, 김성진, 안혜민
    - 통신 → 박하민
    - DB, 인프라(영상 저장, 배포) → 안혜민
    - REST API, 프론트 같이(대시보드 구성) → 윤현준
    - AI → 김성진
    - 로그, 테스트 → 모두가 형식을 맞춰서 해야 함.

| 식별자 | 상위 요구사항명 | 설명 | 구현 계획 |
| --- | --- | --- | --- |
| RE-SF1 | 회원 및 권한 관리 | 관제실 관리자의 계정과 시스템 접근 권한을 관리한다. 신고자는 회원 계정을 만들지 않는다. |   • 관리자는 사전 생성된 계정과 ADMIN 세션으로 로그인한다.
  • 사건 등록·수정·상태 변경·종료는 ADMIN 세션과 CSRF 토큰을 요구한다.
  • 신고자는 사건조회번호와 전화번호로 최소 진행 상태만 조회한다. |
| RE-SF2 | 실종 신고 및 사건 관리 | 관리자가 실종 신고를 사건으로 등록하고 인상착의, 사진, 마지막 목격 위치·시각을 통합 관리한다. |  1. 사건 접수
  • 관리자 대시보드에서 신고자 스냅샷, 실종자 정보, 구조화 인상착의와 마지막 목격 정보를 입력한다.
  • 사건 기본 정보는 JSON API로 등록하고 선택 사진은 별도 사진 API로 업로드한다.

2. 데이터 저장
  • 사건 정보와 신고자 정보는 MySQL에 저장한다.
  • 실종자 사진은 AWS S3에 저장하고, 개발 환경에서는 MinIO를 사용한다.
  • 파일 저장 경로와 파일 정보는 MySQL에서 관리한다.

3. 사건 상태 관리
  • 사건은 접수, 탐색 중, 후보 발견, 종료 등의 상태로 구분한다.
  • 관리자가 사건 내용을 조회하고 상태를 변경할 수 있도록 한다. |
| RE-SF3 | 실종자 탐색 조건 관리 | 신고 정보를 바탕으로 자연어 인상착의, 탐색 시간대, CCTV 및 구역 등 사건별 탐색 조건을 설정한다. |  1. 인상착의 조건
  • 관리자가 입력한 성별, 출생연도, 의류, 소지품 등의 정보를 자연어 탐색 문장으로 구성한다.
  • 관리자가 자연어 조건을 확인하고 수정할 수 있도록 한다.

2. 텍스트 특징 생성
  • 자연어 인상착의는 CLIP 텍스트 인코더를 이용하여 특징 벡터로 변환한다.
  • 생성된 특징 벡터는 녹화 영상 및 실시간 영상의 후보 유사도 비교에 사용한다.

3. 탐색 범위 설정
  • 마지막 목격 시각을 기준으로 탐색 시간대를 설정한다.
  • Kakao Maps JavaScript SDK를 사용하여 탐색 구역과 CCTV를 선택한다.
  • 설정된 조건은 사건별로 저장하여 녹화 영상 및 실시간 영상 탐색에 사용한다. |
| RE-SF4 | 녹화 CCTV 영상 기반 실종자 탐색 | 실종 예상 시각부터 현재까지의 녹화 영상에서 탐색 조건과 유사한 실종자 후보를 검색한다. |  1. 영상 저장
  • CCTV 영상을 H.264 형식으로 녹화한다. **(확인 필요**)**
  • FFmpeg를 사용하여 영상을 일정 시간 단위의 MP4 파일로 분할한다. **(몇분?)**
  • 영상 파일은 AWS S3에 저장하고, 개발 환경에서는 MinIO를 사용한다.
  • CCTV 식별 정보, 촬영 시작·종료 시각, 파일 저장 경로 등의 영상 정보는 MySQL에 저장한다.

2. 분석 대상 선정
  • 사건의 탐색 시간대와 선택된 CCTV를 기준으로 분석할 녹화 영상을 조회한다.
  • 분석 요청은 RabbitMQ를 통해 비동기 작업으로 처리한다.

3. 영상 분석
  • FFmpeg를 이용하여 녹화 영상에서 프레임을 추출한다.
  • 사람 검출 모델로 사람 영역을 추출한 후 CLIP 기반 모델로 탐색 조건과 유사도를 계산한다.
  • 추출된 사람 이미지와 사건별 사진·자연어 탐색 조건의 유사도를 CLIP 기반 모델로 계산한다.
  • 설정된 유사도 임계값 이상의 결과를 실종자 후보로 생성한다.
  • 연속된 프레임에서 동일하거나 유사한 사람이 반복 검출된 경우 하나의 후보로 통합한다.

4. 결과 저장
  • 후보 이미지와 탐지 전후 영상 클립은 AWS S3에 저장하고, 개발 환경에서는 MinIO를 사용한다.
  • 사건 ID, CCTV 정보, 탐지 시각, 유사도, 파일 저장 경로 등의 후보 정보는 MySQL에 저장한다. |
| RE-SF5 | 실시간 영상 기반 실종자 탐색 | 실시간 CCTV 영상에서 실종자와 유사한 후보를 탐지하고 관제실 관리자에게 알림을 제공한다. | 1. 영상 입력
  • 라즈베리파이5 1개 & 노트북 web 카메라 3대
      ◦ resolution
      ◦ FPS : 10fps
 
2.영상 전송 
  • CCTV(라즈베리파이&노트북) → Jetson : RTSP (실제 CCTV도 RTSP 사용)
  • Jetson → 서버 : REST API
  • CCTV(라즈베리파이&노트북) → 서버 : WebSocket

3. 잿슨처리 
  • CLIP (이미지 인코더 구조를 그대로 가져와서 확장) - 필요에 따라 자체 데이터로 fine-tuning  
  • DH-ViT (지식 증류를 활용하여 CLIP기반의 자체 모델 구현) - 이미지 맥락을 이해하는 동시에 이미지로부터 추출 대상인 객체를 후처리하는 기능 추가 
  • OrinDH(TensorRT로 컴파일해서 Jetson에서 빠르게 돌게 최적화)

3.1 Jetson Orin Nano 개발환경
  • OS: Ubuntu (JetPack, Python 3.10.12)
  • 컨테이너: Docker (jetson-containers)
  • 실행 이미지: dustynv/nanoowl:r36.4.0
  • 모델: NanoOWL (OWL-ViT + TensorRT), CLIP (tree prediction용)
  • 엔진 파일: owl_image_encoder_patch32.engine
  • 데모: tree_demo.py (웹 UI, 포트 7860)

3.2 윈도우 PC 개발환경 
  • OS: Windows
  • 가상환경: venv (Python 3.12)
  • GPU: NVIDIA GeForce RTX 4070 Laptop GPU
  • CUDA: 13.1 (드라이버 기준, PyTorch는 cu130 빌드 사용)
  • PyTorch: 2.13.0+cu130
  • 주요 라이브러리: transformers, CLIP(OpenAI), opencv-python, jupyter, ipykernel

4. 정보 전송
  • 전송 조건 : AI 모델이 계산한 인상착의와의 유사도가 설정된 임계값 이상
  • 전송 데이터
      ◦ 메타데이터 (JSON) : 탐지 시각, 카메라 식별자, Bounding Box 좌표
      ◦ 이미지 데이터 : 대상자의 크롭 이미지 파일

5. AI 후보 이벤트 표준화
  • Jetson에서 전송하는 후보 정보를 표준 AI 이벤트 형식으로 정의
      ◦ 후보 이벤트에는 이벤트 ID, 카메라 ID, 영상 촬영 시각 등의 정보를 포함
  • AI 모델과 백엔드가 동일한 JSON 필드명과 자료형을 사용하도록 메시지 명세를 작성

6. AI 후보 이벤트 검증 및 저장
  • 서버는 후보 이벤트를 수신한 후 다음 정보를 검증
      ◦ 존재하는 사건인지 여부
      ◦ 등록된 Jetson과 카메라에서 전송한 이벤트인지 여부
      ◦ 필수 데이터의 누락 여부 등
  • 이벤트 ID에 고유 제약조건을 적용하여 동일한 이벤트가 재전송되더라도 중복 저장하지 않는다.
  • 영상 촬영 시각과 서버 수신 시각을 각각 저장하여 전송 및 처리 지연시간을 확인할 수 있도록 한다.
  • 동일 사건, 카메라와 Track ID에서 짧은 시간 동안 반복 탐지된 결과는 하나의 후보로 통합한다.
  • 통합 후보에는 최초 탐지 시각, 마지막 탐지 시각, 최고 유사도, 평균 유사도와 탐지 횟수를 저장

7. 실시간 후보 알림
  • 후보 이벤트의 검증과 데이터 저장이 완료되면 WebSocket과 STOMP를 통해 관제 대시보드에 실시간으로 전달
  • 관제 화면은 사건별 Topic을 구독하여 해당 사건의 후보 이벤트만 수신
  • 실시간 알림에는 후보 이미지, 탐지 시각, 카메라 정보, 위치와 유사도를 포함
  • WebSocket 연결이 끊긴 동안 발생한 후보는 REST API를 통해 다시 조회할 수 있도록 한다.

8. 테스트용 AI 이벤트 생성
  • 실제 Jetson 및 AI 모델 연동이 완료되기 전에도 백엔드와 프론트 개발을 진행할 수 있도록 가상 AI 이벤트 생성기를 구현
  • 가상 이벤트 생성기는 실제 AI 이벤트와 동일한 JSON 형식을 사용
  • 정상 이벤트, 중복 이벤트, 필수 필드 누락, 미등록 장치와 잘못된 유사도 등의 테스트 데이터를 생성 |
| RE-SF6 | 실종자 후보 검토 및 판정 | AI가 제시한 후보 이미지, 영상, 시각, 위치 및 유사도를 관제자가 확인하고 대상 여부를 판정한다. | 1. 후보 정보 제공
  • AI가 탐지한 후보 이미지, 탐지 전후 영상, 탐지 시각, CCTV 위치 및 유사도를 관제 화면에 제공한다.
  • 후보 목록은 @tanstack/vue-query를 이용하여 조회하고, 신규 후보는 WebSocket과 STOMP를 통해 실시간으로 반영한다.

2. 후보 비교
  • 실종자 신고 사진과 후보 이미지를 함께 표시하여 관제자가 비교할 수 있도록 한다. **(실종자 사진을 받아야하지 않을까?)**
  • 후보 영상은 HTML5 Video를 통해 재생한다.
  • Kakao Maps JavaScript SDK를 이용하여 후보가 탐지된 CCTV 위치를 지도에 표시한다.
 
3. 관리자 판정 및 이력 저장
  • 관제자는 후보를 일치, 불일치, 판단 보류 상태로 판정한다.
  • 판정 결과와 관리자 의견은 MySQL에 저장한다.
  • 동일 후보에 대한 관리자 간 동시 수정을 방지하기 위해 JPA @Version 기반 낙관적 락을 적용한다.

4. 판정 결과 처리
  • 일치로 판정된 후보는 실종자 목격 정보와 추정 동선에 반영한다.
  • 불일치 후보는 수색 대상에서 제외하되 판정 이력은 유지한다.
  • 판정 시각은 UTC로 저장하고 관제 화면에는 KST로 표시한다. |
| RE-SF7 | 실종자 추정 동선 관리 | 관제자가 확인한 목격 정보를 시간과 CCTV 위치 순서로 연결하여 실종자의 이동 동선을 제공한다. | 1. 목격 정보 생성
  • 관리자가 일치로 판정한 후보를 실종자의 목격 정보로 등록한다.
  • 목격 정보에는 탐지 시각, CCTV 위치, 후보 이미지 및 판정 정보를 포함한다.
  • CCTV 위치는 MySQL Spatial POINT 타입과 SRID 4326을 사용하여 저장한다.

2. 동선 구성
  • 확인된 목격 정보를 탐지 시각 순서로 정렬한다.
  • 동일 CCTV에서 짧은 시간 안에 반복 확인된 후보는 하나의 목격 구간으로 통합한다.
  • 가장 최근에 확인된 목격 위치와 시각을 별도로 관리한다.

3. 지도 시각화
  • Kakao Maps JavaScript SDK를 사용하여 확인된 CCTV 위치를 지도에 마커로 표시한다.
  • 목격 위치를 시간 순서대로 연결하여 실종자의 추정 이동 동선을 제공한다.
  • 각 마커에서 탐지 시각, 후보 이미지 및 CCTV 정보를 확인할 수 있도록 한다.

4. 동선 갱신
  • 새로운 후보가 일치로 판정되면 기존 동선에 목격 위치를 추가한다.
  • 잘못 판정된 후보가 수정되면 해당 목격 정보를 동선에서 제외하고 이동 경로를 다시 구성한다. |
| RE-SF8 | 수색 정보 공유 | 확인된 목격 위치, 시각, 수색 구역과 사건 진행 상태를 신고자 및 관계자(담당 경찰관 등)에게 권한에 따라 제공한다. | 1. 권한별 정보 제공
  • Spring Security와 JWT를 이용하여 사용자 권한에 따라 조회 가능한 정보를 구분한다. **(신고 사이트랑 관제 사이트 어떻게 접근 관리할건지?)**
  • 관리자는 사건 정보, 후보 목록, CCTV 위치 및 판정 이력을 조회할 수 있다.
  • 신고자는 본인이 신고한 사건의 진행 상태와 공개가 승인된 수색 정보만 조회할 수 있다.
  • 담당 경찰관 권한은 추후 별도 ROLE로 확장할 수 있도록 구성한다. **(추후 role인가?)**

2. 신고자 사건 조회
  • 신고자는 전화번호와 사건 조회번호를 이용하여 본인이 신고한 사건을 조회한다.**(아직 확정x)**
  • 사건의 접수, 탐색 중, 후보 확인, 수색 중, 종료 등의 진행 상태를 제공한다.
  • 미확정 후보, 내부 CCTV 식별 정보 및 관리자 정보는 신고자 화면에 노출하지 않는다.

3. 수색 정보 제공
  • 관리자가 확인하고 공개한 목격 위치, 목격 시각 및 수색 구역을 제공한다.
  • 위치 정보는 Kakao Maps JavaScript SDK를 이용하여 지도에 표시한다.
  • 시간 정보는 서버에 UTC로 저장하고 사용자 화면에는 KST로 표시한다.

4. 상태 변경 알림
  • 사건 상태 또는 공개된 수색 정보가 변경되면 WebSocket과 STOMP를 통해 접속 중인 사용자 화면에 반영한다.
  • 접속하지 않은 신고자를 위한 문자 알림은 추후 외부 메시지 서비스와 연동할 수 있도록 확장한다. |
