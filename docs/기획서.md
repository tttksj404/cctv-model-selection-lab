# AI 기반 골든타임 실종자 후보 탐색 및 CCTV 동선 지원 시스템 기획서

> 문서 구분: 이 문서는 제품 목표와 계획 범위를 설명한다. AI Worker 자동 분석, Jetson 카메라 4대 탐색, 경로 예측과 Tailscale 운영 구성은 현재 구현을 선언하는 내용이 아니며 단계적으로 구현할 목표다. 실제 제공 기능은 [REST API 명세서](<./API 명세서.md>)의 현재 제공 계약과 `dev` 코드를 기준으로 확인한다.

# 1. 프로젝트 개요

AI 기반 골든타임 실종자 후보 탐색 및 CCTV 동선 지원 시스템은 실종 신고 후 48시간의 골든타임 안에 유의미한 후보 단서를 빠르게 확보하기 위한 스마트 관제 시스템이다. 사건이 등록되면 마지막 목격 장소·시각을 기준으로 AI Worker가 녹화본을 탐색하고, 중앙 서버는 후보의 이동 경로와 카메라 위치를 바탕으로 후속 탐색 작업을 등록한다. Jetson은 관할 카메라의 실시간 후보를 탐지하며, 관리자는 이를 최우선으로 확인한다.

## 1.1 핵심 문제

기존 CCTV 관제는 사람이 영상을 순차 재생하고 후보를 판단하는 비중이 크다. 본 시스템은 별도 객체 탐지 모델을 결합하지 않고, 프레임 전체와 사전 정의된 다중 크롭에 대해 CLIP 이미지·텍스트 유사도를 계산한다. 따라서 ‘검은색 셔츠·청바지·성인 남성’처럼 사건마다 달라지는 자연어 조건을 즉시 검색 조건으로 반영할 수 있다. 골든타임에는 과거 녹화본과 현재 유입 영상을 함께 확인해야 하므로, 후보를 좁혀 관제자의 검토 부담을 줄이는 보조 시스템이 필요하다.

## 1.2 핵심 원칙

- 사건별 자연어 조건을 입력으로 사용하고, CLIP의 이미지·텍스트 유사도로 추가 학습 없이 초기 후보 탐색을 시작한다.
- AI Worker의 과거 녹화본 탐색과 Jetson의 실시간 영상 탐색을 함께 운영한다.
- Jetson·AI Worker 내부 선별 정책을 통과한 후보로 관측 추정 경로를 만들고, 관리자 확정 후보는 별도 확정 경로로 관리한다.
- 실시간 후보는 우선 검토 대상으로 표시하되, 신원 확정은 관리자가 수행한다.
- 개인정보 최소수집, 권한 통제, 보관기한, 감사 로그와 신고자 진행 상태 공유를 MVP 수용 기준에 포함한다.

# 2. 기획 배경과 문제 정의

실종 수색은 최초 목격 시점, 마지막 위치, 인상착의, 이동 가능 방향을 빠르게 정리하는 일이 중요하다. 그래서 텍스트 또는 이미지 기반으로 CCTV의 후보를 찾고 목격 시각·카메라 정보를 바탕으로 경로를 지원하는 접근을 제시한다. 본 프로젝트는 이 문제 맥락을 소규모·동의 기반 MVP로 구체화한다.

사회적 ‘48시간 골든타임’은 프로젝트가 참고하는 문제 맥락이며, 시스템이 48시간 안에 사람을 자동으로 찾아낸다는 성능 약속이 아니다. CLIP은 추가 학습 없이 자연어 조건으로 초기 후보 탐색을 시작할 수 있는 장점이 있지만, 조명·가림·유사 의상에 따라 실행 모델별 후보 선별 정책 조정과 관제자 확인이 필요하다. 선별 기준은 Jetson·AI Worker 내부에서 관리하며 관리자 UI나 Backend API의 사건별 설정으로 노출하지 않는다. MVP의 성과는 후보 검색 시간, 후보 검토 품질, 실시간 알림 지연, 기록의 재현 가능성으로 측정한다.

# 5. 사용자 여정

## 5.1. 신고자 사용자 여정

### 5.1.1. 페르소나

**차자정 씨**는 관계 기관에 실종 정보를 전달한 뒤 관리자로부터 사건조회번호를 안내받은 신고자다. 별도 회원 가입 없이 현재 수색 진행 상황을 명확하게 확인할 수 있는 서비스가 필요하다.

### 5.1.2. 사용자 목표

- 관계 기관과 관리자에게 수색에 필요한 정보를 정확하게 전달한다.
- 발급받은 사건조회번호를 안전하게 보관한다.
- 현재 수색이 어느 단계까지 진행됐는지 확인한다.
- 검증된 관측 정보를 통해 대상자의 상태와 위치를 파악한다.

### 5.1.3. 사용자 여정 지도

| 여정 단계 | Behavior | Pain Point | Feeling | Needs |
| --- | --- | --- | --- | --- |
| **1. 신고 정보 전달** | 관계 기관 또는 관제 관리자에게 연락해 마지막 목격 정보와 인상착의, 사진을 전달한다. | 긴박한 상황에서 어떤 정보가 필요한지 판단하기 어렵다. | 불안함, 초조함, 긴박함 | 필수 정보 안내, 개인정보 이용 범위 설명 |
| **2. 사건번호 수령** | 관리자가 사건을 등록한 뒤 전달한 사건조회번호를 확인한다. | 번호를 분실하거나 접수 여부를 오해할 수 있다. | 걱정, 작은 안도감 | 명확한 접수 안내와 사건조회번호 전달 |
| **3. 탐색 진행 상황 확인** | 사건조회번호와 신고 전화번호를 입력해 ‘접수 → 탐색 → 후보 확인 → 수색 → 종료’ 상태를 확인한다. | 상태가 오래 바뀌지 않으면 신고가 누락됐다고 느낄 수 있다. | 기다림, 답답함, 작은 기대감 | 이해하기 쉬운 진행 단계와 최소 정보 제공 |
| **4. 검증된 관측 정보 확인** | 관리자가 검증한 CCTV 관측 시각과 구역을 확인한다. 필요하면 관계 기관의 안내에 따라 추가 정보를 제공하거나 현장 대응을 준비한다. | AI가 제시한 후보가 실제 대상자인지 확신하기 어렵다. 검증되지 않은 정보가 노출되면 잘못된 장소로 이동하거나 혼란이 커질 수 있다. 민감한 CCTV 영상이 과도하게 제공될 수 있다는 우려가 있다. | 희망, 긴장, 안도감, 여전한 걱정 | 관리자 검증을 완료한 정보만 제공, 관측 신뢰 근거 표시, 이해하기 쉬운 위치·시간 정보, 개인정보 보호, 관계 기관의 후속 행동 안내 |
| **5. 대상 확인 및 신고 종료** | 대상자의 안전 여부와 발견 결과를 확인한다. 사건 종료 안내를 받고 필요한 후속 절차를 수행한다. | 사건이 종료된 이후에도 기록과 개인정보가 어떻게 처리되는지 알기 어렵다. 발견되지 않은 경우 다음 대응 절차가 불명확할 수 있다. | 안도감 또는 지속되는 불안감, 피로감 | 명확한 종료 상태, 후속 조치 안내, 정보 보관·삭제 정책 설명, 상담 및 지원 기관 연결 |

### 5.1.4. 핵심 서비스 요구사항

- 별도 가입 없이 사건번호와 전화번호로 접근하는 **진행 조회 창구**
- 관리자에게 전달받은 사건번호를 이용하는 **최소 인증 방식**
- 현재 상태와 다음 절차를 보여주는 **수색 진행 대시보드**
- 관리자 검증을 마친 관측 정보만 제공하는 **신뢰 기반 정보 공개**
- 상태 변경과 추가 정보 요청을 전달하는 **실시간 알림 기능**

## 5.2. 관제실 관리자 사용자 여정 지도

### 5.2.1. 페르소나

**여기용 씨**는 경찰과 행정 인력의 실종자 수색을 지원하는 관제실 관리자다. AI가 제시한 점수만으로 대상자를 확정하지 않고, 사건 정보와 CCTV 후보의 근거를 종합적으로 검토하여 수색에 필요한 관측 순서와 구역을 전달한다.

### 5.2.2. 사용자 목표

- 신고 정보를 바탕으로 탐색 조건을 정확하게 설정한다.
- AI가 탐색한 후보를 빠르고 신뢰성 있게 검토한다.
- 잘못된 후보를 제거하고 유효한 관측을 연결한다.
- 수색 인력에게 시간과 위치 중심의 실행 가능한 정보를 전달한다.

### 5.2.3. 사용자 여정 지도

| 여정 단계 | Behavior | Pain Point | Feeling | Needs |
| --- | --- | --- | --- | --- |
| **1. 신고 사건 등록** | 전달받은 신고자 연락처, 실종자 정보, 구조화 인상착의와 마지막 목격 정보를 확인하여 사건을 등록하고 사건조회번호를 전달한다. | 신고 정보가 누락되거나 부정확할 수 있고 여러 사건이 동시에 접수될 수 있다. | 긴장감, 책임감, 신중함 | 필수 정보 검증, 구조화 입력, 사건번호 자동 발급, 등록·수정 감사 기록 |
| **2. CCTV 탐색 시작** | 마지막 목격 장소·시각과 인상착의를 등록하면 중앙 서버가 해당 구간의 녹화 분석 작업을 시작한다. | 수동으로 카메라와 시간대를 반복 지정하면 초기 대응이 늦어진다. | 부담감, 집중 | 마지막 목격 정보 기반 자동 작업 등록과 진행 상태 표시 |
| **3. AI 후보 검토** | 녹화본 후보와 Jetson 실시간 후보를 확인하고 ‘후보 유지’, ‘대상 확인’, ‘대상 아님’으로 판정한다. 실시간 후보는 목록 최상단에서 먼저 검토한다. | AI 점수가 높아도 동일 인물이라는 보장이 없고 후보가 많으면 긴급 후보를 놓칠 수 있다. | 의심, 집중, 긴박함 | 후보 출처 표시, 실시간 후보 우선 정렬, 전후 영상과 판정 기능 |
| **4. 후보 타임테이블 및 동선 검증** | 특정 후보를 선택해 관측 시각과 CCTV 구역 순서로 구성된 타임테이블을 확인한다. 카메라 간 이동 시간, 이동 방향과 연결 가능성을 검토한다. | 시간상 이동이 불가능한 관측이 하나의 동선으로 연결될 수 있다. CCTV 사각지대 때문에 경로가 끊길 수 있다. 지도와 영상 정보를 따로 확인하면 판단 시간이 길어진다. | 분석적 집중, 불확실함, 경계심 | 지도와 타임테이블 연동, 이동 가능 시간 검증, 비정상 연결 경고, 관측 근거 표시, 경로 신뢰도와 미확인 구간 표시 |
| **5. 수색 구역 및 현장 대응 결정** | 검증된 관측을 바탕으로 우선 수색 구역, 마지막 확인 위치, 예상 이동 방향과 관측 시간을 경찰·현장 인력에게 전달한다. | 관제 정보가 현장에서 바로 활용하기 어려운 형태로 전달될 수 있다. 오래된 관측 정보가 전달되면 대응 시기를 놓칠 수 있다. 전달 이후 현장 진행 상황을 확인하기 어렵다. | 긴박함, 책임감, 결단력 | 실행 중심의 수색 요약, 마지막 관측 시각 강조, 지도 좌표 및 카메라 위치 공유, 현장 인력과의 양방향 상태 업데이트 |
| **6. 사건 업데이트 및 종료** | 현장 확인 결과를 반영해 후보 상태를 수정한다. 대상 발견 여부를 기록하고 사건을 종료하거나 추가 탐색을 진행한다. 오탐과 판정 결과를 시스템에 피드백한다. | 사건 종료 기준이 불명확할 수 있다. 판정 이력과 수정 이유가 남지 않으면 사후 검토가 어렵다. 오탐 결과가 시스템 개선에 반영되지 않을 수 있다. | 안도감, 피로감, 성취감 또는 아쉬움 | 사건 종료 체크리스트, 판정·수정 이력 기록, AI 결과 피드백 기능, 사건 보고서 자동 생성, 개인정보 보관·폐기 관리 |

### 5.2.4. 핵심 서비스 요구사항

- 신고 정보와 탐색 조건을 한 화면에서 관리하는 **사건 단위 관리 기능**
- 이미지·영상·CLIP 점수·시간·구역을 함께 보여주는 **통합 후보 검토 화면**
- Jetson 실시간 후보를 최상단에 표시하는 **우선 검토 기능**
- 관리자가 직접 후보를 확정하거나 제외할 수 있는 **Human-in-the-loop 판정 구조**
- 관측 추정 경로와 확정 경로를 구분하는 **동선 타임테이블**
- 카메라 위치 기반으로 다음 2개 카메라를 선정하는 **후속 작업 자동 등록**
- 현장 인력에게 바로 전달할 수 있는 **수색 중심 정보 요약**
- 관리자 판단과 AI 결과를 기록하는 **판정 이력 및 피드백 관리**

# 6. 해결 방안과 주요 기능

## 6.1 사건 단위 인상착의 프롬프트

‘검은색 반팔 상의·파란색 하의·남성’처럼 사건별로 달라지는 설명을 구조화 입력하고 Jetson 호환 영어 canonical prompt로 관리한다. 성별, 상의 색, 소매 길이와 하의 색을 필수 구조로 두고 선택적 제외 조건도 같은 구조를 사용한다. CLIP은 이미지와 텍스트를 같은 임베딩 공간에서 비교하므로, 초기 MVP는 새로운 사건마다 별도 모델 재학습을 기다리지 않고 탐색을 시작할 수 있다. 중앙 서버는 프롬프트 정규화 가능 여부를 준비 상태로 제공하되 후보 선별 임계값은 저장하거나 장치에 전달하지 않는다.

## 6.2 이중 시간축 탐색

| 처리 구분 | 입력 | 목적 | 실행 위치 |
| --- | --- | --- | --- |
| 누적 데이터 처리 | 마지막 목격 장소·시각 기준 CCTV 녹화본 | 후보 탐색과 과거 이동 경로 구성 | AI Worker |
| 실시간 데이터 처리 | 관할 카메라 4대의 현재 프레임 | 새 후보를 즉시 관제 화면에 전달 | Jetson Orin Nano |

## 6.3 후보 근거와 관제자 확인

후보 이벤트는 사건 ID, 카메라 ID, 탐지 출처, 시각, 유사도, 후보 이미지와 전후 클립 참조를 포함한다. Jetson은 모델 버전별 내부 선별 정책을 통과한 후보만 전송하고, 관제 화면은 해당 후보를 목록 최상단에 표시한다. 이 정책의 임계값은 관리자 UI, Backend API와 Device snapshot에 포함하지 않는다. 표시 우선순위와 관리자 판정 상태는 분리하며 시스템은 신원을 자동 확정하지 않는다.

## 6.4 동선 지원과 즉각 대응

실행 주체의 내부 선별 정책을 통과해 등록된 후보는 시간순으로 연결하여 내부 탐색용 관측 추정 경로를 만든다. 중앙 서버는 최근 경로와 카메라의 실제 위·경도를 기준으로 다음 예상 카메라를 최대 2대 선정하고, 예상 도착 시각 전후 구간의 녹화 분석 작업을 AI Worker에 등록한다. 관리자가 확정한 후보는 별도 확정 경로로 관리하며, 수사자료에는 확정 경로와 그에 따른 예측 결과만 포함한다.

# 7. 시스템 구성과 AI 처리 흐름

| 구성 요소 | 역할 | MVP 판단 |
| --- | --- | --- |
| 고정 CCTV 4대 | 실시간 영상 입력과 과거 녹화본 제공 | Jetson 1대의 관할 카메라 |
| Jetson Orin Nano | 한 사건에 대해 카메라 4대의 실시간 추론과 후보 전송 | 실시간 발견 담당 |
| 서버·백엔드 | 사건·후보·경로 관리, 다음 카메라 예측과 작업 등록 | 탐색 흐름 제어 |
| AI Worker | 중앙 서버가 등록한 녹화 분석 작업 수행 | 과거 영상 탐색 담당 |
| 관제 대시보드 | 실시간 후보 우선 표시, 후보 검토·판정과 경로 조회 | 사람 확인 인터페이스 |
| WebRTC | 필요 시 관제 화면의 저지연 라이브 보기 | 핵심 기능이 아닌 선택 기능 |

# 9. 결론

본 프로젝트의 차별점은 ‘CCTV에 AI를 덧붙이는 것’이 아니라, 실종자마다 다른 인상착의 등을 텍스트 조건으로 즉시 반영하고, 과거·실시간 영상을 하나의 사건 로그와 관제자 검토 흐름으로 묶는 데 있다. MVP는 소규모·동의 기반 환경에서 후보 탐색의 유효성, 실시간성, 운영 안전성을 검증한 뒤 데이터와 장비 성능을 근거로 확장 여부를 결정한다.
