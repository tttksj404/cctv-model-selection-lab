# 실시간 USB 카메라 인상착의 유사도 탐색

## 무엇을 판단하는가

이 데모는 카메라에 보이는 사람을 추적하고 신고 인상착의와 가까운 항목을 표시합니다.
얼굴 인식이나 동일인 재식별을 수행하지 않으며 신원 확정 결과를 출력하지 않습니다.

현재 프로필:

- 회색 반팔
- 검은색 바지
- 안경
- 넘긴 머리

처리 순서:

1. YOLO11이 사람 바운딩 박스를 찾습니다.
2. ByteTrack이 프레임 사이의 사람 트랙을 유지합니다.
3. CLIP ViT-L/14가 안경, 머리, 반팔과 전체 문장 증거를 계산합니다.
4. 픽셀 색상 규칙이 회색 상의와 검은 바지 증거를 계산합니다.
5. 최근 트랙 증거를 완화 평균하고 3회 이상 관측된 후보만 후보 상태로 올립니다.
6. 1위와 2위 유사도점수 차이가 8점 이하면 자동 강조하지 않고 검토가 필요하다고
   표시합니다.
7. 안경, 머리, 반팔 중 하나라도 최소 증거점수를 넘지 못하면 자동 후보로 올리지
   않습니다.

## 점수와 상태의 의미

화면의 0~100 유사도점수는 속성별 휴리스틱 증거를 가중 평균한 값입니다. 정확도나
일치 확률이 아닙니다.

| 상태 | 의미 |
|---|---|
| 인상착의 유사도 높음 | 필수 색상·의미 증거와 종합 점수가 임계값을 넘고 시간 안정화와 후보 간격을 통과 |
| 인상착의 재검토 | 관측이 부족하거나 후보끼리 비슷하거나 중간 점수 |
| 인상착의 유사도 낮음 | 관측 가능한 증거가 인상착의와 충분히 다름 |

하체가 화면 밖이어서 바지를 확인할 수 없으면 `0점 불일치`로 처리하지 않습니다.
`관측 불가`로 표시하고 자동 강조를 막아 사람의 검토가 필요하도록 합니다. 현재
프레임에서 필수 속성을 관측할 수 없으면 이전 값으로 자동 강조하지 않고 즉시 재검토
상태로 내립니다. 속성이 계속 관측되는 동안에만 같은 트랙의 시간 평활화를 적용합니다.

## 실행

```powershell
cd ai-worker
uv sync --extra realtime --frozen
uv run --extra realtime eyesonu-realtime
```

주요 옵션:

```text
--camera-index INTEGER
--yolo-weights TEXT
--device TEXT
--evidence-path PATH
--max-frames INTEGER
--auto-save-interval INTEGER
--headless
```

`--auto-save-interval` 기본값은 0이며 자동 저장이 꺼집니다. 사람이 촬영된 화면은
사용자가 `S`를 누르거나 자동 저장을 명시적으로 켠 경우에만 파일로 남습니다.

프로필은 설명, 색상 타깃, 속성 라벨과 CLIP 프롬프트가 하나의 묶음이어야 합니다.
새 인상착의로 바꿀 때는 `AppearanceProfile` 전체를 함께 변경하고 테스트를 추가합니다.

YOLO 체크포인트는 `models/` 아래의 로컬 파일만 허용하며 매니페스트 SHA-256을 검사한
뒤 로드합니다. 모델을 교체하려면 파일을 배치하고
`configs/realtime_model_manifest.json`에 검증된 해시를 함께 등록해야 합니다.

## 로컬 검증 기록

2026-07-29 RTX 4050 Laptop GPU와 USB 카메라의 파일럿 화면에서 두 사람이 동시에
등장했을 때 기존 구현은 목표 인상착의 트랙 75.8점, 검은 상의 방해 트랙 50.2점으로
분리했습니다. 이 값은 한 장면의 동작 확인이며 일반화 정확도 증거가 아닙니다.

독립 검토에서 다음 결함을 발견한 뒤 수정했습니다.

- 하체 관측 불가를 검은 바지 0점으로 처리하던 문제
- 후보점수를 확률처럼 `%`로 표시하던 문제
- 1위와 2위 후보가 비슷해도 1위를 자동 강조하던 문제
- 화면의 `ID`가 신원 식별자로 오해될 수 있던 표기

최종 구현은 관측 불가, 후보 간격, 시간 안정화를 테스트로 고정하고 화면에
`휴리스틱 점수(확률 아님)`과 `Track`을 표시합니다.

## 서비스 적용 전 추가 게이트

다음 조건을 만족하기 전에는 자동 신원 판정 기능으로 사용하지 않습니다.

- 여러 identity와 distractor가 있는 데이터
- 카메라, 시간, 트랙을 분리한 held-out 평가
- 독립 검수자가 확정한 속성 정답
- Rank-1/mAP, 오탐 거절률, review rate와 속성별 F1
- 운영 카메라별 임계값 보정과 실패 시 검토 전환

실서비스에서는 이 데모가 후보를 줄이고, 중앙의 SOLIDER/CLIP/Qwen 워커와 최종 규칙
엔진이 과거 영상 트랙과 신고 정보를 종합하도록 연결합니다.
